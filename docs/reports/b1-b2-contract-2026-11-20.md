# Integracja równoległych etapów B1 i B2

Baza: 499ca68. Zakres: implementacja B1 i B2 oraz wspólna walidacja.
Dwa procesy robocze GPT-6.2 Astra realizują rozłączne części we wspólnym repozytorium.
Root odpowiada za adapter, zależności, CI, testy integracyjne i ocenę całego diffu.
Nie zaplanowano commita ani pusha w tym zadaniu.

## Własność

| Strumień | Pliki |
| --- | --- |
| B1 | packages/php/jobs i assets; packages/js/ui, scene, babylon, react i vite; generowane zasoby legacy; testy i raport B1 |
| B2 | packages/php/cms; PHP react-bridge; examples/garage-cms poza AssetIntegration; testy i raport B2 |
| Integracja | Wspólne manifesty/lock, CI, granice pakietów, AssetIntegration oraz testy i raport całości |

Pierwszy profil korzysta z małego UI YG, lokalnego storage poza document root,
PHP CLI workera i dostarczonego postera PNG/JPEG. Kolejne adaptery nie są wymagane.
Reguły oraz ceny garażu są przykładem, nie aktualną ofertą Solidne-Garaże.
Node służy tylko do developmentu/builda. HTTP, upload i worker produkcyjny działają w PHP.

## Asset i dostęp

Descriptor v1:

```text
assetVersionId: string
projectId: string
status: queued | processing | ready | failed
modelUrl: string | null
posterUrl: string | null
checksum: string | null
bytes: number | null
```

Tylko ready otrzymuje URL. Plik binarny nie trafia do props ani JSON/Base64.
CMS posiada port AssetCatalog::descriptor(projectId, assetVersionId, viewer): ?array.
Przed publikacją sprawdza zgodność projektu, wersji, stan ready oraz model i poster.
Publiczny odczyt korzysta wyłącznie z opublikowanej rewizji i aktualnej polityki.

Catalog::usesPublishedAsset(projectId, assetVersionId): bool sprawdza samą referencję
publikacji, bez wywoływania AssetCatalog. Dzięki temu polityka pobrania pliku nie
powoduje cyklu. Redaktor uzyskuje dostęp do własnego projektu; gość wyłącznie do
aktualnie opublikowanej wersji. Podpis URL nie zastępuje aktualnej autoryzacji.

Garage\AssetIntegration::connect otrzymuje PDO, SessionAuthenticator, canEditProject,
usesPublishedAsset, storage i signingKey. Udostępnia catalog(), modules() i
listForEditor(). GARAGE_SIGNING_KEY ma co najmniej 32 bajty; przykład nie ma stałego klucza.

Jobs i Assets korzystają z tego samego PDO. Finalizacja zapisuje wersję oraz zadanie
atomowo. Oba moduły rejestrują migracje; boot nie wykonuje DDL. Worker przetwarza
zamrożone bajty, a opublikowane klucze są niezmienne. Ponowienie nie tworzy drugiej wersji.

Upload przesyła fragmenty do 256 KiB. Request::bytes respektuje limit i zachowuje
również pojedynczy bajt ASCII 0; rozmiar całego modelu nie jest limitem JSON props.

## Interfejs

Form, DataTable, Dialog i AssetPicker należą do @yellow-goose/ui.
Strona może deklarować getLayout(page, props), zwracając stabilny WorkspaceShell
z kluczem projektu. Viewport pozostaje ponad wymienianym drzewem strony; nawigacja
w obrębie projektu nie usuwa kamery ani instancji silnika. Wyjście usuwa zasoby.

BabylonViewport otrzymuje asset i configuration z widthMm, depthMm, heightMm oraz
color. Formularz pokazuje cm, API zapisuje całkowite mm, silnik używa metrów.
Wymagana próba: 213 cm → 2130 mm → 2.13 m → 213 cm po ponownym odczycie.
Ceny są całkowitymi jednostkami najmniejszymi i są obliczane przez PHP.

SSR używa postera i nie zawiera silnika browser-only. Kod Babylon jest osobnym
chunkiem klienta. Payload head zawiera kontrolowane title, description, canonical;
nawigacja aktualizuje te metadane. Pierwszy render i hydracja pozostają zgodne.

## Wspólna akceptacja

1. Redaktor loguje się, tworzy garaż, wysyła model i poster, uruchamia workera,
   wybiera ready asset oraz publikuje ofertę.
2. Gość widzi tekst i poster bez JS, po hydracji rzeczywisty model 3D.
3. Formularz konfiguratora, tabela i modal zachowują viewport oraz kamerę.
4. PHP odrzuca manipulację ceną, obcy projekt, niegotowy asset i zapis bez uprawnień.
5. Późniejszy draft nie zmienia opublikowanej rewizji; unpublish wycofuje publiczny odczyt.
6. Ponowienie uploadu/zadania, błędny checksum/format, URI zewnętrzne i stary token
   nie pozwalają zmienić zaakceptowanych bajtów.
7. Profile bibliotek i stara demonstracja zachowują niezależne instalacje i testy;
   lekkie CMS/UI nie pobiera silnika 3D przez samą instalację pakietu.
